THE PROBLEM AND PROPOSED SOLUTION

A lecturer preparing tomorrow’s class already has the chapter. What takes time is deciding what students should learn, designing an activity, writing the quiz and working out how to mark it. A question can ask students to explain a mistake while the marking guide rewards only the final answer. The lecturer has to catch that mismatch before class.

Build a tool that lets a teacher upload the material once and create a lesson plan, grading rubric, flashcard deck and quiz bank. Let the teacher open one question and see the objective it tests, where students practiced it, the passage behind the answer and the criterion used to mark it.

WHAT THE TEACHER CAN DO

1. Upload Markdown or selectable-text PDF lecture notes, syllabus outlines or textbook chapters. Show the extracted passages with stable document IDs and page numbers or headings. Give a useful recovery step for an empty or image-only PDF.
2. Choose the lesson length, learner level, difficulty and Bloom target. Support Remember, Understand, Apply, Analyze, Evaluate and Create. For an advanced analysis question, specify the reasoning the learner must show and award marks for it.
3. Generate a timed lesson with an exit ticket, a rubric with observable performance levels and marks, flashcards with answers, and a quiz bank with question types, explanations and scoring guidance. Assemble a student study guide. Tie factual claims to the supplied passages.
4. Let the teacher inspect, edit and approve the material. A changed item goes back to review. Export the latest revision as Markdown, JSON and a printable PDF. Separate the student handout from the teacher’s quiz answer key.

DEMO AND ACCEPTANCE CHECKS

Create two original samples on printer queues, one Markdown lecture note and one text-based PDF worked example. Explain first-in, first-out (FIFO) and include arrival and service order. Use this live teacher request:

“From these notes, prepare a 45-minute lesson, a grading rubric, six flashcards, six quiz questions and a one-page study guide. Include an introductory and an advanced question about queue order. Explain how to mark the advanced answer and show the supporting passage.”

Run these checks and record expected result, observed result and evidence:
• Educational alignment. Ask who prints first when A arrives before B. Then show jobs arriving A, B, C and printing A, C, B. The advanced answer should identify C in the second position, explain why B must precede C and give A, B, C as the correction. The lesson must give students practice reasoning about order. The marking guide must award credit for the explanation.
• Source support. Ask for the printer’s pages per minute when the notes provide no speed. The response should flag the missing information. Inspect one item of each artifact type against its cited passage and state who or what checked it.
• Review and export. Launch the app and use its ordinary controls. Change one teacher-only rubric descriptor to “Award one mark for explaining why B precedes C.” Reapprove it as a demonstration action. Open all three teacher exports and find the exact revised text. Inspect the student exports for leaked quiz keys. Capture the running UI and an opened export.
• New input and failure handling. Try a fresh file about stacks with a last-in, first-out example. Check that its answers and citations come from the new file. Use local fixtures to exercise an invalid JSON import and a quota failure. Confirm that failed requests preserve teacher edits.
• Impact. Time one run from upload to reviewed export. Record source size, output counts, number of edits and model calls. Report time savings only with a comparable measured manual baseline. Distinguish passed, failed and unrun checks.
